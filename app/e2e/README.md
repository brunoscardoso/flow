# Flow E2E tests (Playwright + Electron)

End-to-end tests that launch the **built** Flow app and drive its real UI, so
regressions in wiring, IPC, and rendering are caught the way a user would hit
them — not just at the unit level.

## Running

```bash
# From app/ — builds the app, then runs the whole suite (headed Electron):
npm run e2e

# Faster iteration when out/ is already built:
npm run e2e:run

# Interactive UI mode (pick/watch tests):
npm run e2e:ui

# Open the HTML report after a CI run:
npm run e2e:report
```

> **In-session only.** Playwright launches a real Electron window, so run these
> in an interactive session or CI (with a virtual display) — **not** from the
> headless heartbeat daemon, where the window can't render reliably.

### Prerequisites

- `npm run build` has produced `out/main/index.js` (the `e2e` script does this).
- Native modules (`better-sqlite3`, `node-pty`) are built for the Electron ABI.
  If a launch fails with `ERR_DLOPEN_FAILED`, run `npm run rebuild` first.

## How it works

- `fixtures/electron.ts` launches the built app against a throwaway
  `--user-data-dir`, so every test starts from a clean, isolated state (a fresh
  dir means first-run: **No project**, **No threads yet**).
- `fixtures/electron.ts` also takes an `appEnv` option (`test.use({ appEnv: … })`)
  for specs that need the launched app's environment changed — a key mapped to
  `undefined` is deleted rather than blanked. The thread-worktree specs use it to
  point the agent at an empty config dir and strip the inherited auth tokens, so
  a spec that sends a message can never reach the developer's real account.
- `selectors.ts` centralizes DOM selectors (the renderer has no `data-testid`s;
  selectors track the `fl-*` class convention). Update it when shell markup moves.
- Tests run serially (`workers: 1`) — one Electron instance at a time.

## Coverage

| Spec | Feature area |
|------|--------------|
| `smoke.spec.ts` | App boot + renderer mount |
| `shell.spec.ts` | Titlebar, sidebar, side panel, status bar |
| `threads.spec.ts` | Thread search + empty state |
| `sidebar-toggle.spec.ts` | Sidebar show/hide (titlebar + ⌘B) |
| `side-panel.spec.ts` | Files / Review tab switching |
| `terminal.spec.ts` | Terminal toggle (button + ⌃`) |
| `tasks-board.spec.ts` | Kanban board opens |
| `blueprint.spec.ts` | Blueprint view opens |
| `settings.spec.ts` | Settings overlay open/close/Escape |
| `composer.spec.ts` | First-run conversation state + composer gating |
| `pr/` | Per-PR regression specs generated by the QA heartbeat |

### Known gate

Flows that need a **project + Claude account** (sending a message, agent runs,
git commit, review generation) aren't exercisable from a fresh, credential-less
launch, and the "Add project" flow opens a native OS folder picker Playwright
can't drive. Those paths are covered by the QA heartbeat's static verification
today; unlocking them in E2E needs seeded state or mocked IPC (future work — see
the `pr/` specs and `flow/pr-verify-runbook.md`).

## Adding tests

1. Add/confirm selectors in `selectors.ts`.
2. Create `<feature>.spec.ts`, import `{ test, expect }` from `./fixtures/electron`.
3. Use the `window` fixture (the app's first window) and assert on **observable**
   behavior (a click reveals X, a toggle hides Y) — not internals.
4. `npm run e2e:run` and confirm green before committing.
